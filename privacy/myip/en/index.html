Privacy Policy — My IP Address - Public & Local

Last updated: October 13, 2026 · 한국어

Owlmakers explains how My IP Address - Public & Local handles information.

Key points
· No account or sign-in is required. There is no developer server or proxy for the IP lookup function.
· Public IP lookup connects to the external HTTPS service ipify only after you request a lookup and confirm the notice. Your IP may remain in the external service's records. We do not guarantee anonymous connections or no logging.
· Local addresses, DNS, gateways, SSIDs, saved records and backup contents are not included in developer, advertising or analytics events. Selected sharing sends the chosen information to the app you choose.
· AdMob, Google Analytics for Firebase and developer usage statistics (Pulse) communicate over the network separately. The app is not fully offline and does not claim that all data stays on your device.

1. Public IP lookup

After you request a lookup and confirm the notice, the app connects to https://api.ipify.org for IPv4 and https://api6.ipify.org for IPv6. The external service sees the connection IP and may keep it in operational or access records. Local addresses, DNS, SSIDs, history and backup files are not sent as request payloads. The developer does not proxy the request or store the lookup IP on a server.

Service information: https://www.ipify.org

We have not verified the service's terms of use, commercial-use conditions or actual retention period. Permission to use it in an advertising-supported app requires human confirmation before release. We do not guarantee service availability or absence of logs.

2. On-device information

  • The app displays interface addresses, connection type, DNS and gateway information provided by the device. Some values may be unavailable depending on Android version and network.
  • The current Android implementation does not request location permission and does not read the SSID. Unavailable information is marked accordingly.
  • Results are stored on the device only when you select fields and save a record. A record can contain addresses, query time, source, connection type and selected fields. There is no automatic background IP lookup or automatic IP history.
  • Theme, language and onboarding preferences are stored locally.
  • Delete selected or all records in History. This does not delete copies already exported or shared to another app.

3. Copy, sharing and backup

Copy places the original value on the system clipboard. Sharing sends selected fields to another app after a confirmation preview. The receiving app's policy applies afterwards. Sensitive fields such as SSID are excluded by default.

A backup file contains saved history and settings. Advertising and analytics device-specific keys are excluded. Files can contain sensitive IP information, so choose storage and recipients carefully. Files are saved to the device's download storage and are not uploaded to the developer. They may remain after uninstalling the app and can be deleted with a file manager. Restore validates the selected file and merges it locally after your confirmation.

4. Google AdMob advertising

The app uses a top banner and a native ad in the exit confirmation. It does not show interstitial ads during lookup, copying or saving. The advertising SDK starts after the UMP consent flow. Where required, a consent form may appear. Privacy options in Settings let you change your choice when available.

AdMob may collect and share connection IP addresses (for approximate location), product interactions, diagnostics, advertising IDs, app set IDs and other applicable identifiers for advertising, analytics and fraud prevention. Lookup IP values, SSIDs and shared text are not supplied as advertising parameters. The SDK's own network connection may reveal the connection IP separately. Data is encrypted in transit using TLS.

Google advertising information: https://policies.google.com/technologies/ads

You can reset or delete your advertising ID in Android settings.

5. Firebase and Pulse usage statistics

Google Analytics for Firebase may collect app-instance and advertising IDs, sessions, screens, device and app information, and approximate location derived from masked IP addresses. Additional app events contain only action names (lookup, cancel, copy, share, save), address-family names and selection counts. They do not include addresses, SSIDs, interface names, shared text or backup files. Google policy: https://policies.google.com/privacy

Release builds send screen and action names, counts, app version, displayed language, ad-click format and active-use signals to the developer's shared statistics endpoint https://api.owlmakers.com/v1/pulse. A new random session value is generated for each run; it is not a persistent device identifier. The server uses country, region and city names provided by the intermediary service for usage statistics. Under the Pulse contract it does not store raw IP addresses or coordinates. Raw statistics are retained for one year. No app account or IP lookup history is stored there. Servers and intermediaries can see connection IP addresses during network communication.

6. Permissions and services

Internet, network-state and advertising-ID access support lookup, advertising and statistics. The app does not request location, contacts, camera, microphone or account permissions. It does not use push notifications or Firebase Messaging. Restore reads only a file you choose. Update notices use Google Play in-app updates.

7. Deletion, children and contact

Clear app storage or uninstall to remove local app data. Delete backup files separately with a file manager. Advertising identifiers and data processed by Google follow Google's controls and policies. For developer statistics questions or deletion requests, email support@owlmakers.com. As the developer does not collect accounts or persistent device identifiers, individual statistics may not be identifiable.

The app is not designed for children under 14. Changes are announced on this page with the revision date.
