개인정보처리방침 — 카드 실적 관리 - 정기결제·고정지출

시행일자: 2026년 10월 20일 · English

핵심 요약
· 카드·지출 정보는 기기 안에 저장되며 개발자 서버로 전송되지 않습니다. 사용자가 「폰 연결」을 직접 켠 경우에만 공유로 고른 카드의 결제가 종단 간 암호화되어(운영자·Google 도 읽을 수 없음) 상대 폰으로 전달됩니다(2-다).
· 카드 승인 문자는 「문자 가져오기」 등을 실행할 때와, 사용자가 켠 경우의 실시간 수신에서만 읽습니다. 알림은 사용자가 「알림으로 결제 읽기」를 켠 경우에만, 지정한 앱의 결제 알림만 읽고 나머지는 내용을 보지 않고 버립니다. 원문은 서버로 전송하지 않으며 처리 전까지만 앱 전용 저장소에 임시로 둡니다.
· 광고(AdMob)·이용 통계(Google Analytics for Firebase)·자체 사용 현황판(Pulse)은 아래 2-라 항목대로 통신합니다.

「카드 실적 관리 - 정기결제·고정지출」(이하 "앱")는 사용자의 개인정보를 매우 중요하게 생각하며, 대한민국의 「개인정보 보호법」 및 Google Play 정책을 준수합니다. 본 개인정보처리방침은 앱이 어떠한 정보를 처리하고, 어떻게 보호하는지 설명합니다.

1. 기본 원칙 (No-Backend, Local-First)

본 앱은 별도의 회원가입, 로그인 계정 체계, 운영자의 중앙 데이터베이스 서버가 없는 로컬 우선(Local-first) 앱입니다. 사용자가 입력하거나 기기에서 생성된 모든 금융·카드·소비 관련 데이터는 사용자의 기기 내부(SharedPreferences)에 저장되며, 운영자의 서버로 전송되지 않습니다.

단, 이용자가 [설정] → [폰 연결]을 직접 켜서 다른 사람의 폰과 연결한 경우에만 이용자가 고른 카드의 결제 정보가 종단 간 암호화되어 Google 이 운영하는 클라우드 저장소(Google Cloud Firestore)를 거쳐 상대 폰으로 전달됩니다(2-다 항목). 이 기능을 켜지 않으면 위 원칙 그대로 어떤 결제 정보도 기기 밖으로 나가지 않습니다.

2. 처리하는 개인정보 및 기기 데이터의 항목

가. 사용자가 직접 입력하여 기기에 저장되는 정보 (폰 연결을 켜지 않는 한 서버 전송 없음)

  • 카드 관리 정보: 카드 이름(별칭), 기준 실적 금액, 결제일, 실적 인정 기준
  • 카드 사진(선택): 이용자가 직접 고른 사진을 카드 모양으로 잘라 자른 결과만 이 앱 전용 저장소에 저장합니다. 고른 원본 사진은 보관하지 않으며, 다시 저장하므로 촬영 위치 등 부가 정보도 따라오지 않습니다. 서버로 전송하지 않습니다.
  • 지출 및 실적 내역: 고정지출 항목명, 결제 예정일, 결제 금액, 월별 실사용 금액 내역
  • 저장 위치: 이용자 기기 내부 저장소 (SharedPreferences)

나. 문자(SMS)·알림 데이터 처리 (기기 안에서만 처리, 서버 전송 없음)

  • 문자 처리 항목: 단말기 수신 문자 중 카드 결제 관련 문자(승인·취소·결제 키워드 포함 메시지)의 일시, 금액, 가맹점, 카드 정보(카드명·끝 4자리, 그리고 카드사가 문자에 가려서 보낸 결제자 이름(예: 홍*동))
  • 알림 처리 항목(이용자가 [설정] → [알림으로 결제 읽기]를 켠 경우에만): 카카오뱅크·토스뱅크 앱의 카드 결제 알림, 카카오톡의 카드사 알림톡 중 결제·취소 안내의 일시, 금액, 가맹점, 카드 정보
  • 처리 목적: 카드 실적 집계 편의를 위한 결제 내역 자동 추출
  • 결제자 이름의 쓰임: 같은 카드사의 가족카드처럼 번호 끝자리가 없는 문자에서 서로 다른 카드를 구분하기 위해서만 씁니다. 앱은 이름을 직접 가리거나 풀어 보지 않고 문자에 온 모양 그대로(가려진 채) 기기에만 저장하며, 카드 연결 정보로 백업 파일에도 담깁니다.
  • 문자 처리 방식: [문자 가져오기]·[문자로 카드 찾기]·앱을 열 때의 반영은 기기 내부 메모리에서만 일시적으로 대조·파싱하며, 원문은 디스크에 저장되지 않습니다. [문자 오는 즉시 등록]을 켠 경우 결제 문자로 보이는 문자만 처리가 끝날 때까지 이 앱 전용 비공개 저장소(자동 백업 제외)에 임시로 두었다가 처리 직후 삭제하고, 결제 문자가 아닌 문자는 즉시 버립니다.
  • 알림 처리 방식: 안드로이드의 알림 접근 설정상 이 기능을 켜면 앱이 모든 알림을 전달받지만, 지정한 앱(카카오뱅크·토스뱅크·카카오톡의 카드사 알림톡)의 결제 알림이 아닌 알림은 내용을 읽지 않고 즉시 버립니다. 결제 알림은 처리가 끝날 때까지만 위와 같은 비공개 저장소에 두었다가 처리 직후 삭제합니다.
  • 외부 전송: 문자·알림 원문은 외부 서버로 일절 전송되지 않습니다. 최종적으로 등록된 금액·날짜·가맹점·카드 정보(결제자 이름 포함)만 기기 로컬에 저장되며, 이용자가 폰 연결을 켠 경우에만 그중 이용자가 공유하기로 고른 카드의 등록 결과(원문 아님)가 아래 「다」처럼 암호화되어 전달됩니다.

다. 폰 연결 (선택 기능 — 이용자가 직접 켠 경우에만)

두 사람이 각자의 폰에서 연결을 맺으면, 한 폰에서 읽은 카드 결제를 다른 폰의 앱에서도 볼 수 있습니다. 연결은 한 폰이 만든 12자리 초대 코드를 상대가 입력해야 맺어지고, 보내는 쪽과 받는 쪽이 각자 승인해야 흐르며, 공유할 카드도 이용자가 직접 고릅니다(새 카드는 기본으로 공유하지 않음).

  • 전달되는 정보: 공유하기로 고른 카드의 결제 일시·금액·가맹점·승인번호·분류(해외 결제는 원래 통화·외화 금액·환산 추정 여부 포함), 카드 설명(카드사·별칭·끝 4자리), 연결 때 이용자가 정한 표시 이름, 보내기·받기 승인 상태. 문자·알림 원문은 전달되지 않습니다.
  • 어떻게 보호되나: 위 정보는 기기에서 만든 비밀키로 종단 간 암호화(AES-256-GCM)되어 올라갑니다. 비밀키는 초대 코드로 한 번 감싸서 두 폰에만 전달되고, 각 폰의 안드로이드 보안 저장소에 두며 자동 백업에 포함되지 않습니다. 운영자와 Google 을 포함해 두 폰 밖의 누구도 암호를 풀어 내용을 읽을 수 없습니다.
  • 어디에 두나: Google LLC 가 운영하는 Cloud Firestore(서울 리전)를 우편함으로 씁니다. 운영자는 자체 서버를 두지 않습니다. 이 과정에서 앱이 만든 임의의 익명 식별자(Firebase 익명 로그인)와 기기 임의 번호, 올린 시각·크기 같은 내용과 무관한 정보는 Google 쪽에서 처리될 수 있습니다.
  • 보관·삭제: 받는 폰이 가져가면 그 즉시 우편함에서 지우며, 가져가지 않은 것도 올린 폰의 앱이 올린 지 최대 30일 안에 지웁니다(앱을 열지 않으면 더 남을 수 있음). 초대 코드는 10분 뒤 쓸 수 없고 수락되면 삭제되며, 수락되지 않은 초대 문서는 암호화된 채 남을 수 있습니다. 연결을 끊으면 이 폰의 비밀키가 삭제되고 올린 메시지와 이 폰의 제어 문서가 지워지며(오프라인 등으로 지우지 못하면 앱이 다음에 다시 지웁니다), 먼저 끊은 쪽의 «떠났다» 표시(암호화됨)는 상대가 끊을 때 함께 지워집니다(상대가 끊지 않고 앱을 지우면 암호화된 제어 문서 1개가 남을 수 있습니다).
  • 받는 쪽의 데이터: 상대 폰에서 받은 결제는 받은 폰에 기기 내부 데이터로 저장되며(위 「가」와 같음), 연결을 끊어도 지워지지 않고 이쪽 앱에서 직접 삭제하거나 앱 데이터를 지울 때까지 남습니다. 연결은 믿는 사람과만 맺어 주세요.
  • 끄는 법: [설정] → [폰 연결]에서 보내기·받기 승인을 끄거나, 일시 중지하거나, 연결을 끊을 수 있습니다.

라. 백업 및 복구 데이터

  • 사용자가 직접 [설정] → [백업] 기능을 실행할 때 생성되는 파일은 순수 텍스트(JSON) 형태로, 사용자가 지정한 로컬 경로에만 저장됩니다. 외부 클라우드로 자동 전송되지 않습니다.

마. 서비스 품질 모니터링 및 광고 표시를 위해 자동 수집·전송되는 정보

본 앱은 서비스 안정성 개선 및 광고 서비스 제공을 위해 아래와 같은 최소한의 기술적 데이터를 외부 전문 서비스(제3자 도구)를 통해 수집 및 전송할 수 있습니다.

  1. 자체 서비스 사용 현황 모니터링 (Owl Pulse):
    • 전송 대상: https://api.owlmakers.com/v1/pulse
    • 수집 항목:
    • 앱 식별 정보: 앱 패키지명(com.owlmakers.cardusage), 앱 버전, 표시 언어
    • 세션 식별자: 앱 프로세스 실행 시 생성되는 임의의 32자리 난수 세션 ID (sid, 프로세스 종료 시 소멸하며 기기 고유 식별자가 아님)
    • 앱 내 이벤트: 화면 전환 내역, 버튼 탭 식별자(코드 형태의 ID), 광고 클릭 여부, 앱 활성 상태 유지를 위한 하트비트(15초 주기)
    • 대략적인 위치: 서버가 접속 IP 로부터 국가·시·도·도시 이름만 추출해 통계에 쓰며, IP 주소 자체와 위경도는 저장하지 않습니다.
    • 철저한 배제: 이용자의 금융 정보, 카드 번호, 결제 금액, SMS 본문, 성명, 연락처 등 일체의 개인 식별 정보는 절대로 포함되지 않습니다.
  2. Google AdMob (광고 서비스):
    • 수집 항목: 광고 식별자(ADID/IDFA), IP 주소, 기기 정보, 광고 상호작용 데이터
    • 수집 목적: 앱 내 광고(상단 배너, 목록 사이 네이티브, 앱 종료 화면 네이티브) 노출 및 광고 성과 측정, UMP(User Messaging Platform)를 통한 이용자 동의 관리
  3. Google Analytics for Firebase (GA4):
    • 수집 항목: 익명화된 앱 이용 통계(화면 뷰, 기본 인터랙션 이벤트), 기기 모델, OS 버전
    • 수집 목적: 앱 기능 오류 분석 및 이용 통계 파악

3. 개인정보의 보유 및 이용 기간

  • 기기 내 저장 데이터: 앱 삭제(제거) 또는 앱 데이터 삭제 시 기기에서 즉시 영구 파기됩니다.
  • 문자(SMS)·알림 데이터: 원문은 파싱 직후 메모리에서 해제됩니다. 실시간 수신·알림 읽기에서는 처리가 끝날 때까지만 앱 전용 비공개 저장소에 임시로 두고 처리 직후 삭제하며(처리하지 못한 것은 최대 3일 뒤 삭제), 원문은 서버에 전송·보관되지 않습니다.
  • 폰 연결 우편함 데이터(선택 기능): 위 「2-다」의 보관·삭제 기간을 따릅니다(받으면 즉시, 늦어도 올린 지 30일 안에 앱이 삭제).
  • 모니터링 및 분석 데이터(Pulse / GA4 / AdMob): 각 수집 시스템의 통계 보관 정책에 따라 일정 기간 보관 후 집계된 통계 데이터로만 활용됩니다.

4. 개인정보의 제3자 제공 및 위탁

앱은 원칙적으로 이용자의 개인정보를 외부에 제공하지 않습니다. 다만, 서비스 운영 및 광고 표시를 위해 아래의 제3자 SDK를 연동하여 사용하고 있습니다.

5. 이용자의 권리와 행사 방법

  1. 알림 읽기 끄기·권한 철회: 앱의 [설정] → [알림으로 결제 읽기]를 끄면 알림을 더 이상 처리하지 않으며, 단말기의 [설정] → [알림] → [기기 및 앱 알림] (알림 접근)에서 이 앱의 허용을 해제할 수 있습니다.
  2. SMS 권한 철회: 이용자는 언제든지 단말기의 [설정] → [애플리케이션] → [카드 실적 관리] → [권한] 메뉴에서 SMS 읽기 권한을 철회할 수 있습니다. 권한을 철회해도 수동 입력을 통해 앱을 제한 없이 이용할 수 있습니다.
  3. 데이터의 파기: 이용자가 앱을 삭제하거나 단말기 설정에서 앱 데이터를 삭제하면 기기에 저장된 모든 카드 및 실적 데이터가 즉시 삭제됩니다. 폰 연결을 쓴 경우에는 먼저 [설정] → [폰 연결] → 연결 끊기로 우편함의 내 메시지를 지우는 것을 권장하며, 상대 폰이 이미 받아 저장한 결제는 상대 폰에서 삭제해야 합니다.
  4. 광고 개인정보 설정: 동의가 필요한 지역(EEA·영국 등)에서는 앱 내 [설정] → [광고 개인정보 설정] 메뉴를 통해 Google UMP 동의 설정을 언제든지 재설정할 수 있습니다. 그 밖의 지역에서는 기기의 광고 설정(Google 설정 → 광고)에서 맞춤 광고를 끌 수 있습니다.
