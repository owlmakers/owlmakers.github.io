Privacy Policy — Tally Counter - Haptic Click

Last updated: October 13, 2026 · 한국어

Owlmakers explains how Tally Counter - Haptic Click handles information.

Key points
· No accounts, sign-in or server for counting. Current counts, completed records and settings are stored on your device.
· Shake sensors run only after you start them while the app is in the foreground. Leaving the screen or the app stops them; they do not restart automatically. Raw samples are not stored or transmitted.
· The app uses Google AdMob, Google Analytics for Firebase and shared usage monitoring (Pulse). Names, backup contents and raw sensor samples are not transmitted.

1. Local information

Count names, values, goals, previous values, completed records and dates, haptic, keep-awake, sensitivity, language, theme and onboarding settings are saved locally. Backups contain settings and records and are saved in Downloads. A safety copy is kept inside app storage before restoration.

Result images are created when you choose to save or share them. Sharing sends them to the app you choose in the device share sheet, subject to that app's policy.

2. Sensors and permissions

Accelerometer samples are read only during counting you explicitly start in the foreground. There is no continuous or background sensor collection. The app uses vibration permission. It does not use camera, microphone, location, contacts, account or push notification permissions. Restoration reads only the file you select. Internet, network state and advertising ID permissions support ads and analytics.

3. Ads

Google AdMob ads may appear in a top banner and the exit confirmation window. The SDK may collect and share advertising and app set IDs, IP address (for approximate region), interactions and diagnostics for ads, analytics and fraud prevention. Transmission uses TLS. Count names and raw sensor samples are not provided to ads.

Where required, UMP consent is handled before starting the ad SDK. Ad privacy settings allow changes when available.

Google ad policy: https://policies.google.com/technologies/ads

4. Usage analytics

Firebase Analytics receives screen views, action names and counts for increases, decreases, goals, completion and starting shake counting. Automatic SDK data may include app instance ID, advertising ID, sessions, device and app information, and approximate region derived from IP. Count names, file paths, backup contents, raw sensor samples and precise location are not sent. Google policy: https://policies.google.com/privacy

Pulse sends app, version, display language, screen, action names and counts, ad click format and activity signals to https://api.owlmakers.com/v1/pulse. It uses a new temporary session ID each run rather than a permanent device ID. The server aggregates country, region and city names without retaining IP addresses or coordinates. Raw usage records are retained for one year for usage analysis. Counting remains functional when this shared monitoring server is unavailable.

5. Deletion and choices

Clear app data or uninstall to remove internal data. Delete backup files from Downloads and saved result images separately; they may remain after uninstalling. Records can be deleted in the app. Reset or delete the advertising ID in your device's Google ad settings. There is no app account to delete. You do not need to send count names or backup contents when contacting support.

6. Children and changes

The app is not directed to children under 14. Policy changes are announced on this page.
